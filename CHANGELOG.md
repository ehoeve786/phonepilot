# Changelog

## Unreleased

- M1: repository skeleton with build-logic, `core/model`, `core/common`, the app shell in `oss`, `pro` and `play` flavors, the module graph guard and CI.
- M2: local MCP server. `core/audit`, `core/orchestrator` (registry, dispatcher, sessions), `core/tools` with `device.info`, `capability/api` and `capability/device`, `server/mcp` (MCP SDK mapping) and `server/http` (Streamable HTTP on 127.0.0.1:8765 with a local bearer token). The app runs the server in a foreground service and shows the token and the Claude Code command.
- M3: eyes and hands. `capability/accessibility` (Accessibility service for snapshots, node actions, gestures and screenshots), `capability/apps` (launcher apps, launch, links), `capability/screencapture` (WebP/JPEG/PNG encoder) and `core/imaging` (crop, redact, scale, dHash). New tools: `screen.snapshot`, `screen.find`, `screen.wait_for`, `screen.wait_for_change`, `screen.capture`, `ui.tap`, `ui.long_press`, `ui.swipe`, `ui.type_text`, `ui.press_key`, `ui.global_action`, `app.list`, `app.current`, `app.launch`, `app.open_url`. Tool errors now repeat the error code and recovery hint in the text. `app.stop` and `app.send_intent` wait for Shizuku (M4) and the policy engine (M5).
- M4: Shizuku. `capability/shizuku` runs a privileged service as the shell user for input, raw screenshots, `uiautomator` snapshots, the foreground app, launches and the status bar. `core/capabilities` picks a backend per call in spec priority order, routes an element to the backend that took its snapshot, and falls back to Shizuku when Accessibility is off. Actions now wait for the screen to settle before the follow-up snapshot. Doctor v1 on the home screen shows each capability's backends and Shizuku's state, with a button to allow PocketPilot in Shizuku.
- M5: secure remote access. `network/api` and `network/tailscale` (an embedded tsnet node built with gomobile that joins the owner's tailnet and forwards HTTPS, including Tailscale Funnel, to a second loopback port), `server/oauth` (the phone's OAuth 2.1 server: metadata, dynamic registration, PKCE, rotating refresh tokens, revocation, lockout), `core/policy` (rate limits, app deny list checked before and after screen actions, confirmations for sensitive and destructive tools), `feature/approvals` (consent and confirmation prompts) and `feature/clients` (connected apps and the kill switch). The remote port accepts OAuth tokens only; the local token keeps working for apps on the phone. Debug builds are signed with a shared key so CI APKs update in place.
- M6: more networks. `network/wireguard` (userspace WireGuard on its own network stack, from a wg-quick config), `network/zerotier` (libzt built from source, joins a ZeroTier network and waits for approval), `network/certificates` (Let's Encrypt certificates for the owner's domain through Cloudflare DNS, renewed 30 days before expiry, and an optional DNS record that follows the relay), `network/public-access` (ready-to-paste relay setups for OpenWrt and GL.iNet routers, nginx and Caddy, plus the server's WireGuard peer) and `feature/network` (the Your own network card). The Go networking moved to `network/gonet`, shared by Tailscale and WireGuard, since a process holds one Go runtime. Secrets are encrypted with a Keystore key.
